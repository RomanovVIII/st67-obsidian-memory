# Explicit thread completion

Run only for a direct instruction to finish the thread (for example, “завершить тред”), not a farewell or a discussion of this procedure. This is reconciliation and scoped cleanup; archiving the chat requires a separate instruction. Unfinished tasks do not become completed because the conversation ends.

## Reconcile the work

1. Use the objects, owners and verified results already known in this task. Refresh the affected cards/records as needed; do not read entire bases or repeat an unchanged topic search.
2. Update necessary confirmed knowledge at the existing owners. Review related TODOs, plans and active problems against their acceptance criteria. Close only completed work through the local lifecycle; keep incomplete checks and open questions with existing owners. No thread registry or duplicate handoff record.
3. Check changed documents, moved/deleted old paths and affected links with the local Link Workflow. Complete mandatory project finishing actions already authorized by the task. A link check does not prove infrastructure acceptance.

## Confirm cleanup roots and candidates

Determine the actual task-related raw/inbox and tmp/temp directories from project/base rules or known task paths. Do not infer a broad cleanup root from a common folder name. Missing directories are normal. Check only those existing working directories, not OS `%TEMP%`, neighboring projects, other bases or another agent's workspace. Enumerate task candidates, then inspect unknown objects narrowly; do not recursively open everything.

Raw/inbox: normally retain originals. Under this explicit finish request, a current-task material can be deleted only when all of these are established:

- its useful knowledge has been transferred and verified;
- an exact original has a confirmed permanent copy, with matching cryptographic checksum (a summary is not a copy);
- no active reference depends on the temporary original;
- it is unnecessary for continuation, incomplete verification or recovery.

Tmp/temp: delete only materials created by this agent for the current work whose purpose is unambiguously exhausted. Preserve useful results, evidence for incomplete checks and recovery material. A directory name, age or apparent duplication alone is not evidence that a file is expendable.

Keep old, foreign and unclear objects for the user's decision. Report each candidate's path, established or presumed purpose, reason for retention and proposed action; say explicitly when purpose is unknown. Do not treat silence as deletion approval.

## Delete and verify

The explicit finish request authorizes only cleanup meeting the conditions above. Check every candidate's resolved absolute path remains inside its confirmed permitted working directory, including symlink/junction targets; do not follow a link to delete elsewhere. Never delete a whole directory's contents indiscriminately. Prefer deleting individual confirmed files; remove an empty task-created directory only after checking it contains no retained material.

Verify permanent copies before deleting raw, search affected references (including ordinary Markdown/plain routes where applicable), then verify deleted paths are absent and retained materials remain. Re-run the affected link check after cleanup and do applicable journal entries once. Do not rewrite historical records solely to make a removed path into a current link; record deletions as plain paths when local rules require history.

End with a short account of saved results, open work, removed material, and retained cleanup candidates. Do not archive the chat or close unfinished work automatically.
