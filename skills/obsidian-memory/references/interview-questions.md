# Interview Questions

Ask only questions that the read-only scan cannot answer. Prefer concise batches of 1-3 questions.

## Essential Decisions

1. What is the memory root folder name and location?
2. Is the memory root an Obsidian vault, or a folder inside an existing vault?
3. What is the project scope and what should stay outside it?
4. Should old docs/context/wiki material be migrated, archived, or only used as reference?
5. Which knowledge roles should be enabled for this project?
6. Which changes may Codex record automatically, and which require explicit approval?
7. Is this a new base, a migration, existing-base maintenance, or a validation-only task?

## Role Map Questions

Use these when the role map is unclear:

- Do you need a current-state owner for confirmed facts, or is this project only a task log?
- Do you need a procedure owner for reusable rules, checks, or runbooks?
- Do you need a problem owner for analyzed issues and troubleshooting cards?
- Do you need a todo/open-question owner for deferred checks and uncertain current-state questions?
- Do you need a research owner for future options and comparisons?
- Do you need a planning owner with plan rules and active technical plans?
- Do you need a decision owner with decision rules, strategic decisions, and accepted technical choices?
- How does the existing lifecycle retain completed plans and distinguish them from accepted choices?
- Do you need a separate completed-work owner for work that is not represented as decisions?
- Do you need a raw-input owner for temporary user-provided files?
- Do you need an archive owner for manual archive material?

## Planning And Decision Questions

- Does the project need a master/project plan separate from technical plans?
- What should the plan rules file be called?
- What naming pattern should technical plans use?
- Should technical plans be checklist-only or include short context sections?
- What should the decision rules file be called?
- Should strategic/project decisions be cumulative in one register?
- What naming pattern should technical decision records use?
- Which useful source plans/results should a decision reference?

## Update Policy Questions

- Should Codex update memory after every durable project change or only when asked?
- Should logs be created automatically after changes, or only after explicit instruction?
- What acceptance criteria and retention policy apply when closing plans?
- Should side topics solved during a thread be added to the plan only after user confirmation?

## Migration Questions

- Which old material is current truth, historical context, or obsolete?
- Should uncertain facts go to the todo/open-question owner instead of current-state files?
- Should migration be done now or planned separately?
- Is broad rule optimization allowed as part of this migration?

## Existing-Base Maintenance Questions

- Which files or owners changed and must be checked locally?
- Is a local check enough, or did the user explicitly ask for full inventory?
- Which local rules override the generic skill model?
- Are there moved or renamed files whose incoming links must be checked?

## Obsidian Questions

- Do you want Obsidian wiki-links, Markdown links, or both?
- Should attachment folders be part of the memory root?
- Should file names be localized or stable English slugs?
