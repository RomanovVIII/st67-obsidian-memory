# Agent integration

Use only when designing or changing a requested agent integration. Preserve existing local routing instead of inserting a duplicate block. A request to implement the integration authorizes the edit; otherwise present a concrete proposal before changing agent rules. Generate actual paths and enabled owners, omitting absent roles.

## Example block

```markdown
# Project memory

`<memory_root>/` is the project knowledge base. For a substantive project task, choose its owner and read the base index and canonical maintenance rule, then only relevant cards/procedures. Reuse unchanged instructions and known context in the continuing task.

Use `obsidian-memory` for targeted prior-work lookup at first use on a topic, topic changes or an explicit database search. Preserve the existing ownership, paths and lifecycle. Confirmed updates necessary to an authorized task need no repeated approval; structural expansion and valuable irreversible deletion require agreement.

Follow the actual base Link Workflow when present; otherwise use the installed skill Link Workflow for local link/index checks. Full audits require a new base, major migration/reorganization or an explicit request. Automated checks do not replace semantic or live-state verification.

Close completed work by its acceptance criteria; preserve unfinished work. Record accepted choices separately from plan results. Never store secrets or create conversation registries. On an explicit command to finish the thread, use `obsidian-memory` reconciliation and conditional cleanup. Chat archiving requires a separate instruction.
```

## Apply and verify
