# Approved migration

Map source documents, owners, identities and destinations before edits. An ordinary maintenance request does not migrate an existing base. Preserve existing names, required paths and lifecycle until migration is explicitly authorized. Read [naming-and-numbering.md](naming-and-numbering.md) only when adopting naming-v1; read only the template sections needed for the selected destinations.

Establish a permanent namespace, designated allocator and high-water marks from issued IDs, including history, removed records and reservations. Unknown historical maxima are an open decision; do not guess reusable IDs. Adopt schema v3 only with the approved naming migration. Preserve logical ownership and hierarchy separately.

Distinguish verified current facts, history, uncertainty and obsolete material. Work in bounded batches; preserve originals or verified recovery copies, repair incoming/outgoing links and index entries, verify each batch. Do not replace an original with a summary when it is needed for continuation/recovery. No full copies, symlinks/junctions or wiki links between independent bases; use plain owner routes.

PLN/TRB closure is a new completed identity with retained source_id, not a silent prefix rename. Follow agreed retention/lifecycle policy. Never turn every completed plan into a decision. Conclude a major migration with full structure/link audits of each base separately; compare other bases only for names. Validate content meaning separately. Report uncertain facts and unresolved migration items at their existing owners.
