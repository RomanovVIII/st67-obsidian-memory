# Existing-base maintenance

Use the base index and canonical rule already read for this task. Preserve local owners, paths, names, exclusions, language, freshness markers and lifecycle. Do not reshape a working base to match the new-base examples.

## Point work

- Reuse targeted prior-work matches from the skill entry; search again only when the object/scope or relevant records change.
- Read the affected card and only required related procedures. Update confirmed durable facts at their existing owner; historical sources and research are not automatically current truth or accepted decisions.
- Close TODOs, plans and problems only after their actual criteria are met. Preserve incomplete checks, questions and follow-up work at existing owners. Completion of a plan records an outcome; a decision records an accepted choice and rationale. One does not automatically become the other. Follow a base's existing closure mechanism without silently redesigning it.
- Register new/moved managed Markdown in the existing index, honoring exclusions; repair affected backlinks. Avoid repeating the same fact in multiple cards. Do not manufacture links just to remove an orphan advisory.
- Use the local Link Workflow for checks and applicable journaling. Full audit is reserved for an explicit request, new base or major migration/reorganization. Reuse an identical required check instead of running it twice.

## Authority and material

The task authorizes necessary updates within its scope. Ask only about a genuine missing decision, scope expansion, structural change or valuable irreversible deletion, not each authorized edit. Unrelated cleanup is outside point maintenance. Raw originals normally remain; for an explicit thread finish use the conditional completion procedure.

## Meaning versus mechanics

Check the edited facts against supplied/verified evidence and their owner. Review whether an uncertainty, plan, decision or completed result is represented honestly. Then perform the automated local structure/link checks. Neither a historical note nor successful link lint substitutes for verification of changing infrastructure.

For naming-v1, read naming-and-numbering only when allocating/renaming/closing a record; consult the appointed allocator and CFG high-water marks. Existing-card edits do not require creation, migration, naming or template references. When the canonical rule is the installed skill, this maintenance procedure satisfies that read; do not create duplicate local rules.
