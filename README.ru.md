# 🧠 ST67 Obsidian Memory

## Дайте ИИ-агенту память, которая не исчезает после закрытия чата.

**Обычно работа ИИ заканчивается вместе с разговором: новый сеанс не знает всего, что вы уже объясняли и решали раньше. ST67 Obsidian Memory превращает временный контекст разговоров в постоянную, структурированную память проекта, к которой агент может возвращаться в следующих сессиях.**

![ST67 Obsidian Memory](assets/st67-obsidian-memory-hero.png)

Проще говоря, это **вторая память для вашего ИИ-агента**. Вместо того чтобы полагаться только на текущий чат, агент может создавать и поддерживать базу знаний проекта: подтверждённые факты, решения, задачи, инциденты, правила, историю и связи между ними.

Для использования не нужно хорошо разбираться в Obsidian. Память хранится в обычных Markdown-файлах, которые остаются понятными и доступными человеку. Obsidian даёт удобный интерфейс и связи между заметками, но не является обязательным.

ST67 Obsidian Memory — Agent Skill для OpenAI Codex, который помогает агенту безопасно создавать, обслуживать, читать и проверять эту долговременную память проекта.

### ⚡ Что меняется, когда у агента появляется память?

**Без постоянной памяти:**

- полезный контекст остаётся в старых чатах;
- в новой сессии приходится повторно объяснять уже известные вещи;
- решения, факты и история проекта расползаются по разным разговорам;
- разные агенты могут сформировать разные версии одного и того же факта.

**С ST67 Obsidian Memory:**

- важные знания проекта сохраняются между сессиями;
- агент понимает, где должны храниться подтверждённые сведения;
- решения, задачи, инциденты, правила и история остаются связанными;
- новая сессия может начинаться с накопленных знаний проекта, а не с нуля;
- база остаётся читаемой человеком и находится под вашим контролем.

### 🧩 Для реальных проектов

Skill подходит для:

- нового проекта, где базы знаний ещё нет;
- существующего набора Markdown-файлов и заметок;
- Obsidian vault;
- долгоживущих проектов с ИИ;
- проектов с несколькими агентами и участниками;
- проектов со своей структурой, правилами именования и документами — источниками истины.

Skill **не заставляет** все проекты использовать одну универсальную структуру папок. Существующие `AGENTS.md`, индексы, локальные правила и уже определённые владельцы знаний имеют приоритет.

⭐ **Если вы тоже считаете, что ИИ-агент должен помнить проект после закрытия чата — поставьте репозиторию ⭐.** Так проект смогут найти другие пользователи.

## Зачем он нужен

ИИ-агент очень полезен внутри одного разговора, но реальный проект живёт гораздо дольше одной сессии. Для полноценной памяти проекта недостаточно просто сохранять историю чатов: нужно понимать, где находятся актуальные факты, решения, задачи, правила, инциденты, история и как документы связаны друг с другом.

Без такой структуры база знаний постепенно превращается в ещё один набор разрозненных файлов:

- одинаковые сведения хранятся в нескольких местах;
- решения и задачи теряются среди заметок;
- ссылки перестают работать;
- новым участникам непонятно, с чего начинать;
- агент не знает, какой документ является источником истины.

ST67 Obsidian Memory помогает вести эту постоянную память, сохраняя исходные данные и требуя подтверждение перед существенными изменениями.

## Четыре режима работы

### Onboarding

Для новой или хаотичной базы.

Skill:

1. обследует проект только для чтения;
2. находит Markdown-файлы, существующие правила, индексы и возможные vault;
3. выявляет дублирующиеся темы и кандидатов на чувствительные данные;
4. задаёт только те вопросы, ответы на которые нельзя определить автоматически;
5. предлагает короткий код проекта и объяснённую структуру;
6. показывает точный проект настройки;
7. останавливается и ждёт явного подтверждения перед записью.

### Maintenance

Для обслуживания, миграции и реорганизации существующей базы.

Skill следует принятой локальной схеме, обновляет канонических владельцев знаний и не создаёт дублирующие документы или параллельные Wiki.

### Query

Для поиска и ответов без изменения файлов.

Skill начинает с точки входа проекта и отличает подтверждённое текущее состояние от истории, предположений и непроверенных материалов.

### Audit

Для обычной или полной проверки базы только для чтения.

Аудит охватывает структуру, метаданные, индексное покрытие, Wikilinks, заголовки, block references, вложения и границы vault.

## Что получает новичок

После обследования skill может предложить базовый каркас:

```text
<project>/
├── AGENTS.md
└── wiki_<project_slug>/
    ├── decisions_<CODE>.md
    ├── entities/
    ├── inbox/
    ├── incidents/
    ├── index_<CODE>.md
    ├── logs/
    │   └── 0001_LOG-<CODE>_YYYY-MM.md
    ├── rules/
    │   ├── 0001_RUL-<CODE>-database-maintenance.md
    │   └── 0002_RUL-<CODE>-link-workflow.md
    └── todo_<CODE>.md
```

Каждый объект получает понятное назначение:

- единый индекс отражает все постоянные Markdown-файлы и папки;
- TODO содержит только актуальные нерешённые вопросы;
- решения ведутся накопительно, новые записи располагаются сверху;
- журнал разделён по месяцам, новые события находятся сверху;
- каждый существенный инцидент получает отдельную карточку;
- карточки сущностей обновляются на месте;
- `inbox/` хранит непроверенные материалы и не очищается автоматически;
- два обязательных правила закрепляют ведение базы и работу со ссылками.

Дополнительные папки создаются только при подтверждённой необходимости.

## Безопасность onboarding

Onboarding не выполняет без отдельного подтверждения:

- установку или настройку Obsidian;
- замену существующего `AGENTS.md`;
- перемещение, объединение или удаление неоднозначных материалов;
- удаление дублей;
- создание Git-репозитория или резервной копии;
- изменение исходных документов;
- запись секретов в Wiki.

Существующий `AGENTS.md` сохраняется. Skill может только предложить точные совместимые дополнения и показать их до записи.

## Структурный аудитор

Инвентаризация проекта:

```bash
python3 skills/obsidian-memory/scripts/structure_audit.py /path/to/project
```

Полная проверка согласованной структуры:

```bash
python3 skills/obsidian-memory/scripts/structure_audit.py /path/to/project \
  --wiki-root /path/to/project/wiki_example \
  --code EXAMPLE \
  --strict-exit
```

Аудитор проверяет:

- обязательные файлы и папки, включая их тип;
- имена и нумерацию;
- YAML-frontmatter;
- единственность индекса;
- полноту и порядок индексных записей;
- журнал текущего месяца;
- Unicode NFC/NFD;
- кандидатов на чувствительные данные.

Проверка не изменяет проект. Значения предполагаемых секретов и содержимое нераспознанных строк индекса не выводятся. Обнаруженная символическая ссылка, фактическая цель которой находится вне проекта, отклоняется как ошибка входных данных.

Коды завершения:

- `0` — проверка успешна;
- `1` — строгий режим обнаружил нарушения;
- `2` — ошибка входных данных.

## Аудитор ссылок

```bash
python3 skills/obsidian-memory/scripts/link_audit.py /path/to/managed-wiki \
  --vault-root /path/to/current-vault \
  --strict-exit
```

Поддерживаются:

- `[[page]]`;
- `[[folder/page]]`;
- aliases;
- ссылки на заголовки;
- block references;
- `![[note]]`;
- бинарные embeds;
- Markdown-ссылки и вложения;
- Unicode NFC/NFD;
- вложенная Wiki внутри более крупного vault.

Аудитор выявляет битые и неоднозначные ссылки, отсутствующие цели, выход за границу vault, неполное индексное покрытие и документы без достаточных входящих связей. Символические ссылки и пути индекса, фактически ведущие за подтверждённую границу, отклоняются. Небезопасная Markdown-ссылка считается битой без обращения к внешнему пути.

Диагностические строки содержат только безопасный относительный путь исходного файла, категорию нарушения и номер строки. Исходные значения ссылок и устаревших целей индекса не выводятся.

Он работает только для чтения, не использует сеть и не запускает внешние процессы.

## Установка в Codex

### Через Skill Installer

Откройте Codex и попросите `$skill-installer` установить skill из репозитория:

```text
Install obsidian-memory from:
https://github.com/RomanovVIII/st67-obsidian-memory/tree/v0.1.0/skills/obsidian-memory
```

Если новый skill не появился сразу, перезапустите Codex.

### Вручную

Скопируйте каталог:

```text
skills/obsidian-memory
```

в пользовательский каталог skills:

```text
$HOME/.agents/skills/obsidian-memory
```

Codex также поддерживает symlink на каталог skill.

После установки можно вызвать skill явно:

```text
$obsidian-memory
```

Либо описать задачу обычным языком — Codex сможет выбрать skill по его назначению.

## Быстрый старт

Для хаотичной базы:

```text
$obsidian-memory обследуй этот проект и предложи безопасную организацию базы знаний. До моего подтверждения ничего не изменяй.
```

Для обслуживания:

```text
$obsidian-memory проверь локальные правила и обнови базу знаний по результатам текущей работы.
```

Для поиска:

```text
$obsidian-memory найди подтверждённые решения по этой теме. Файлы не изменяй.
```

Для полного аудита:

```text
$obsidian-memory проведи полный аудит структуры и ссылок этой Wiki.
```

## Требования

- Python 3.9 или новее;
- OpenAI Codex для основного сценария использования;
- macOS, Linux или Windows;
- сторонние runtime-зависимости не требуются;
- Obsidian необязателен.

Markdown-правила, шаблоны и Python-аудиторы можно адаптировать для других агентных сред, поддерживающих Agent Skills или совместимый формат инструкций. Такая совместимость должна проверяться отдельно в конкретной среде.
