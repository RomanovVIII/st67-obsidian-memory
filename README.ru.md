# ST67 Obsidian Memory

ST67 Obsidian Memory — Agent Skill для организации и ведения проектных Obsidian- и Markdown-баз знаний. Он может провести новичка через безопасную первичную настройку, а в существующем проекте сохраняет приоритет локальной схемы.

Документация на английском: [README.md](README.md)

## Состояние

Репозиторий находится в состоянии `Unreleased`. Первая планируемая версия — `0.1.0`; release и Git tag пока не создавались.

## Возможности

- разделяет четыре режима работы: onboarding, обслуживание, read-only запрос и read-only аудит;
- инвентаризирует новый или хаотичный проект без изменений;
- задаёт короткую адаптивную анкету, предлагает код проекта и объяснённую структуру Wiki, затем ждёт подтверждения перед записью;
- предоставляет готовые адаптивные шаблоны проектных инструкций, метаданных, единого индекса, актуальных задач, решений, журналов, инцидентов, сущностей, двух базовых правил и предварительного проекта настройки;
- предоставляет стандарт новичка с единым индексом, актуальными задачами, накопительными решениями, месячными журналами, инцидентами, сущностями, входящими материалами и базовыми правилами;
- находит и соблюдает локальные `AGENTS.md`, точку входа и правила;
- сохраняет одного канонического владельца каждого устойчивого факта;
- удерживает Wikilinks внутри текущего vault;
- проверяет структуру onboarding, типы обязательных объектов, имена, нумерацию, метаданные, покрытие индексом и наличие журнала текущего месяца;
- проверяет Wikilinks, заголовки, block references, бинарные embeds, Markdown-ссылки и вложения, слабые входящие связи и нерешённые ссылки `TBD_`;
- учитывает Unicode NFC/NFD в путях;
- поддерживает вложенный корень управляемой базы внутри более крупного vault.

Оба аудитора только читают проверяемый проект и не изменяют его. Runtime-код использует Python 3.9+ и только стандартную библиотеку. Сеть и внешние процессы не используются. Поддерживаемые целевые системы: macOS, Linux и Windows.

Onboarding не устанавливает Obsidian, не меняет его настройки и не реорганизует существующие материалы без отдельного подтверждения. Obsidian необязателен: Markdown-Wiki остаётся пригодной для работы и без приложения.

## Использование

Установите или подключите каталог `skills/obsidian-memory` по правилам обнаружения skills в вашей агентной среде. Идентификатор вызова — `$obsidian-memory`.

Инвентаризация проекта перед onboarding:

```bash
python3 skills/obsidian-memory/scripts/structure_audit.py /path/to/project
```

Полная проверка согласованной структуры:

```bash
python3 skills/obsidian-memory/scripts/structure_audit.py /path/to/project \
  --wiki-root /path/to/project/wiki_example \
  --code EXAMPLE \
  --strict-exit
```

В режиме инвентаризации `--wiki-root` и `--code` не нужны; для полной проверки они передаются только вместе. Коды завершения структурного аудитора: `0` — успех, `1` — строгие структурные замечания, `2` — ошибка входных данных. В результатах указываются только относительные пути и категории; найденные значения предполагаемых секретов и содержимое нераспознанных строк индекса не выводятся.

Запуск аудитора ссылок:

```bash
python3 skills/obsidian-memory/scripts/link_audit.py /path/to/managed-wiki \
  --vault-root /path/to/current-vault \
  --strict-exit
```

Его стабильные входы CLI: `memory_root`, `--index`, `--vault-root`, повторяемый `--index-exclude` и `--strict-exit`. Коды завершения: `0` — успех, `1` — строгие замечания аудита, `2` — ошибка входных данных.

## Разработка

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q skills tests
```

Будущая CI-матрица настроена для Ubuntu, macOS и Windows с Python 3.9 и 3.14. Она не считается фактически пройденной до публикации репозитория и запуска workflow на GitHub.
