# ST67 Obsidian Memory — v0.2.0

Память ИИ-агента, которая сохраняется после закрытия чата. Навык Codex ведёт подтверждённые факты, решения, задачи, проблемы и связи в обычных Markdown-файлах. Obsidian необязателен.

![ST67 Obsidian Memory](assets/st67-obsidian-memory-hero.png)

## Режимы

Короткий SKILL.md направляет к отдельным процедурам создания, миграции, обслуживания, именования, аудита и явного завершения треда. Читаются только нужные материалы, неизменённый контекст используется повторно. При первом предметном обращении и смене темы выполняется адресный поиск по объекту и алиасам в существующих TODO, планах, активных/завершённых проблемах, решениях и результатах. Поиск не изменяет базу и не разрешает найденные дополнительные задачи.

Поручение внедрения разрешает необходимые обновления в его пределах без повторных подтверждений. Проектирование остаётся предложением. Расширение структуры и необратимое удаление ценных материалов согласуются отдельно. Существующие владельцы, пути, имена и lifecycle сохраняются до согласованной миграции. История не доказывает текущее состояние инфраструктуры; автоматическая проверка не заменяет смысловую и фактическую.

## Новый стандарт naming-v1

Минимум: `IDX_ATLAS.md`, `CFG_ATLAS.json` и `LOG_ATLAS-0001_2026-10.md` с первого журналируемого события. Пустые месячные журналы не нужны. TODO появляется при первом открытом вопросе; карточки и папки — по потребности. Общие обслуживание и Link Workflow остаются в навыке, параметры и специальные процедуры — у базы.

Единый словарь: `IDX CFG LOG TODO HOST DEV APP SRV NET STO PLN CPLD TRB CTRB DEC RSR RPT RUL ATT RAW TMP`. Сервисы обозначаются SRV. Постоянный уникальный код базы отделён от логического владельца и необязательной родительской базы. Изменение иерархии не меняет имён файлов.

Нумерованные имена: `TYPE_BASE-NNNN_тема`, с датами для планов/проблем/решений/отчётов/журналов. У каждого типа своя последовательность без повторного использования. Назначенный мастер резервирует номера и сохраняет максимумы в CFG после сбоев/удаления; остальные редактируют существующие документы или готовят содержание. Центрального сервиса выдачи номеров и распределённой блокировки в выпуске нет. Закрытие PLN/TRB создаёт CPLD/CTRB с новым ID и исходным source_id. Завершённая работа не становится решением автоматически. Примеры: [именование](skills/obsidian-memory/references/naming-and-numbering.md), [шаблоны](skills/obsidian-memory/references/file-templates.md).

## Проверка ссылок

```bash
python3 skills/obsidian-memory/scripts/link_audit.py /path/to/base --strict-exit
python3 skills/obsidian-memory/scripts/link_audit.py /path/to/base --changed cards/service.md --strict-exit
python3 skills/obsidian-memory/scripts/link_audit.py /path/to/base --changed cards/new.md --removed cards/old.md --json --strict-exit
```

Повторяемый --changed принимает существующие изменённые документы/вложения, --removed — отсутствующие прежние пути. Точечный режим проверяет затронутые входящие/исходящие ссылки, регистрацию, применимые lifecycle и имена. Посторонние ошибки не влияют на результат; область проверки видна в отчёте. Для разрешения ссылок допускается просмотр имён и ссылок других документов.

Schema v1/v2 поддерживаются; v3 добавляет file_namespace, naming_profile, allocation_owner, last_issued и необязательный parent_base_id. Приоритет: явный --config, затем obsidian-memory.config.json, затем единственный корневой CFG_*.json; несколько кандидатов дают код 2. Без конфигурации остаётся index.md. --index переопределяет индекс.

Сохранены --vault-root, повторяемый --index-exclude, --strict-exit и прежние счётчики. Расширенная граница vault должна принадлежать той же подтверждённой базе; межбазовых Wiki-ссылок нет. Исключения из индекса не отключают проверку ссылок. --compare-root сравнивает только имена, в точечном режиме — затронутые. Уникальность по NFC и без учёта регистра охватывает документы и вложения. Допустимые родительские пути внутри границы разрешены; выход за границу и опасные входные пути/символические ссылки отклоняются. Заголовки и блоки проверяются вне примеров кода; номера строк соответствуют исходному документу.

**По умолчанию нет записи файлов и сети.** --json печатает безопасный отчёт. Только явный --json-out записывает отчёт внутри корня; только явный --check-urls проверяет разрешённые классы URL (в точечном режиме — изменённые документы). Внешние процессы и сторонние зависимости не используются. Текст, JSON и stderr не воспроизводят исходные значения ссылок и данные авторизации URL.

Коды: 0 — выполнено, 1 — строгие нарушения с --strict-exit, 2 — неверные аргументы/конфигурация/границы. Аудит сам ошибки не исправляет.

## Структурный аудитор

```bash
python3 skills/obsidian-memory/scripts/structure_audit.py /path/to/project
python3 skills/obsidian-memory/scripts/structure_audit.py /path/to/base --profile naming-v1 --strict-exit
python3 skills/obsidian-memory/scripts/structure_audit.py /path/to/project --wiki-root wiki_example --code EXAMPLE --strict-exit
```

Старый вызов сохраняет прежний профиль onboarding и счётчики. Явный naming-v1 проверяет новый минимум, ID, счётчики и уникальность; пропуски номеров и месяцы без событий допустимы. Старый профиль к новой базе не применяется. Поиск чувствительных данных выводит категории, а не значения. Оба аудитора работают только для чтения, кроме явно запрошенного JSON-отчёта проверяющего ссылки скрипта.

## Завершение и очистка

Явная команда завершить тред сверяет подтверждённые результаты, связанные задачи и ссылки, сохраняя незавершённое. Проверяются только подтверждённые рабочие raw/inbox и tmp/temp. Исходники обычно сохраняются; удаление требует проверенного переноса знаний, постоянной точной копии оригинала с совпадающей контрольной суммой, отсутствия действующих ссылок и необходимости продолжения/восстановления. Удаляются только однозначно отработанные временные материалы текущей работы агента. Полезные, чужие, старые и неясные объекты остаются и перечисляются пользователю. Системные temp, массовая очистка, автоматическое закрытие задач и архивирование чата не применяются.
